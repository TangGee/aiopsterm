# 飞书 IM 网关

IM 网关把飞书消息接到 aiopsterm 中已经打开的终端。首版支持飞书企业自建应用，通过长连接接收消息，不需要公网回调地址。入口是 **设置 > IM 网关**，默认关闭。桌面应用和目标终端必须保持运行；关闭窗口后终端不可用时，网关不能独立执行命令。

这是显式终端控制：普通聊天只返回帮助，不调用大模型，也不自动建立 SSH 连接。未来渠道可通过适配器接入，当前只能配置一个飞书应用。技术边界见 [IM 网关架构](../technical/im-gateway.md)。

## 配置飞书

1. 在[飞书开发者后台](https://open.feishu.cn/app)创建企业自建应用，启用机器人能力，取得 App ID 和 App Secret。
2. 为应用申请接收单聊消息、以应用身份发送消息的权限。需要群聊时，再申请接收群聊中 @ 机器人的消息权限。在事件订阅中添加 `im.message.receive_v1`。权限及可用范围需要按企业管理要求生效。
3. 在 aiopsterm 的 IM 网关设置里填写 App ID、App Secret 和允许操作的用户 `open_id`。这些 ID 必须属于当前应用，不能用姓名、邮箱或另一应用下的 open_id 替代。可从飞书的用户信息 API 调试结果或开发者后台事件调试数据中取得当前应用的用户 ID；不要将包含凭据或完整消息正文的调试数据公开。
4. 在桌面打开目标 SSH 主机，点击“查看当前终端与资产 ID”，把需要授权的资产 ID 填入授权主机列表。只有勾选“允许访问本机终端”后，本地终端才可用。每项 ID 单独一行，也支持逗号分隔。
5. 勾选启用，保存并应用。连接建立后，在飞书事件配置中选择长连接方式保存，并按飞书流程发布应用版本。设置页显示的是实际连接状态；“设置已保存”不等于“已连接”。如果配置顺序受后台校验限制，先保存凭据并建立连接，再保存事件订阅。
6. 单聊机器人发送 `/sessions`，按返回的 sessionId 执行 `/bind <sessionId>`。先用 `/run pwd`、`/read` 验证绑定的终端正确。

官方参考：[事件处理与长连接](https://open.feishu.cn/document/server-side-sdk/nodejs-sdk/handling-events)、[接收消息事件](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/events/receive)、[官方 Node SDK](https://github.com/larksuite/node-sdk)。

## 命令

| 消息 | 行为 |
| --- | --- |
| `/help` | 查看命令帮助 |
| `/sessions` | 显示已连接且已授权的终端，最多 40 个 |
| `/bind <sessionId>` | 绑定当前用户、当前聊天的终端，不跟随桌面焦点 |
| `/status` | 查看当前绑定 |
| `/unbind` | 解除当前绑定 |
| `/run <单行命令>` | 向绑定终端输入文字并发送回车 |
| `/send <单行文字>` | 仅输入文字，不发送回车 |
| `/read` | 读取当前终端屏幕末尾 40 行，超过长度限制时保留末尾内容 |
| `/interrupt` | 向绑定终端发送 Ctrl+C |

`/run` 不是后台作业接口。若终端正在运行编辑器或另一个交互程序，文字会输入该程序。回执只确认已发送输入，不保证执行成功或完成；稍后用 `/read` 查看屏幕。当前不持续推送输出、不保存命令正文，不提供任意控制字符和多行粘贴。单条输入最多 2048 字符。密码等敏感数据不要通过聊天输入。

群聊必须同时满足：群 `chat_id` 已授权、发送者 `open_id` 已授权、消息明确 @ 当前机器人。命令放在 @ 机器人之后。群内回复和终端输出对所有群成员可见。不同用户、聊天、租户及应用各有自己的绑定；绑定不会继承桌面当前焦点。

终端断线重连或应用重启后，原 sessionId 可能失效，需要重新 `/sessions`、`/bind`。网关不会偷偷切到重建的终端。修改权限、停用网关会停止接收并丢弃尚未执行的排队操作，已经发给终端的命令不会回滚或被自动中断。

## 凭据与排障

App Secret 使用操作系统凭据加密保存，不返回设置页、不进入普通用户配置导出。已保存后留空即可保留。更换 App ID 需要重新填写 Secret。删除 Secret 时先取消启用，再勾选清除并保存。Linux 必须有可用的系统密钥环，不能使用明文回退后端。

- 连接失败：检查 App ID/Secret、机器人能力、网络以及应用权限和发布状态；重新保存会重建连接。
- 已连接但不响应：检查用户 open_id 是否属于当前应用、消息事件是否订阅、用户是否在应用可用范围内。群聊还要检查 chat_id、@ 对象及群消息权限。未授权消息不会得到回复。
- 没有终端：先在桌面打开主机并连接，核对资产 ID 授权；本地终端需要单独允许。
- 命令已发送但看不到结果：使用 `/read`。不要因为消息回复失败就重复发送有副作用的命令；先检查桌面终端。
- 查看 **设置 > 关于 > 打开日志目录** 中的 `aiopsterm-runtime.log`，筛选 `im.gateway`。日志仅记录消息标识、用户/聊天标识、操作类型和结果，不记录命令、终端输出或凭据。

应用 userData 目录下，`im-gateway.json` 保存网关配置与加密 Secret，`im-gateway-state.json` 保存消息去重凭据和绑定。它们不包含命令历史。状态文件损坏时网关拒绝启动；排障时先退出应用、备份文件，不要在运行中清除去重记录。
