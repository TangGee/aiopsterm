# Telegram 与百度如流配置

通用权限、绑定与命令见 [IM 网关](im-gateway.md)，设置入口见 [设置页帮助](settings/zh-CN/im-gateway.md)（[English](settings/en-US/im-gateway.md)）。飞书配置保留在通用指南的“配置飞书”章节。

## 平台选择与凭据

在 **设置 > IM 网关 > 接入平台** 选择飞书、Telegram 或百度如流。当前一次只启用一个平台、一个机器人，不支持三者同时连接。切换下拉框只修改草稿；保存才停止旧渠道并应用新配置。切换会清空草稿中的机器人身份、凭据和用户/群列表，终端资产范围保留以便检查；切回原平台也需要重新填写。已保存配置不会保留各平台的独立凭据档案。

旧版飞书配置仍可读取，不需要迁移。Secret/Bot Token 继续由系统密钥环加密保存，不回传到设置页；机器人 ID、App Key、用户/群 ID 不是密钥。账号、平台或如流 App Key 改变后必须重新填写凭据，不复用旧 Secret。保存后查看连接状态，保存成功不代表平台已经连通。

## Telegram

1. 在 Telegram 找到官方 [BotFather](https://t.me/BotFather)，使用 `/newbot` 创建机器人并取得 Bot Token。将 Token 填入 aiopsterm 的密码框；Bot ID 填 Token 第一个冒号前的数字。不要填机器人用户名，也不要把 Token 发给他人或贴入日志。
2. 先私聊机器人发送一条消息。使用自己的 Bot API `getUpdates` 调试结果取得 `message.from.id`；这是授权用户 ID。群 ID 使用 `message.chat.id`，通常为负数。用户名、显示名称和手机号不能替代数字 ID。若从本地调试 API 获取 ID，先保持 aiopsterm 网关停用，结束调试后再启用，以免两个接收端争抢更新。
3. 填写授权用户、终端资产或本机权限，初次测试将群列表留空。启用并保存，私聊 `/help`、`/sessions`，点击终端按钮，再发送 `pwd`、`/binding`、`/key ctrl c` 和 `/screenshot`。
4. 如需群聊，将机器人加入群并将群 chat ID 加入白名单。在群里发送 `/sessions@机器人用户名`；普通正文使用 `@机器人用户名 pwd`。用户名匹配不区分大小写，群聊裸命令或提及其他机器人不会进入终端。用户也必须在白名单内。
5. 保留 BotFather 默认隐私模式即可使用明确提及的指令。机器人需要群内发消息/文件权限；频道消息、匿名管理员代发、机器人消息和带话题 ID 的消息暂不接入，避免绑定到错误身份或话题。

桌面通过 `getUpdates` 长轮询主动连接 `api.telegram.org`，不需要公网回调。网络必须能访问 Telegram API；此适配器未增加独立代理设置。一个机器人只能由一个轮询实例消费消息。若已有 webhook，启动会拒绝并保留原 webhook；请在确认不再使用旧接收端后自行调用 `deleteWebhook` 或换一个机器人。不会自动删除其他应用的 webhook 或清空积压消息。

终端选择使用 inline keyboard，按钮仅原用户、原聊天、原卡片可用，十分钟后或应用重启后失效。普通文字按 4000 UTF-16 单元分段；不会启用 Markdown/HTML 解释终端输出。TUI 重绘编辑同一条消息，最多显示末尾约 4000 字符；编辑失败会停止输出订阅，不新建消息刷屏。截图以 `terminal.png` 文件发送，保留文字清晰度；不是桌面截图。

参考：[Bot API](https://core.telegram.org/bots/api)、[机器人特性与 BotFather](https://core.telegram.org/bots/features)。

## 百度如流

1. 在如流机器人服务号或企业管理后台创建机器人，不勾选“开通官方智能体”（该模式会托管回调，无法配置本接入所需的长连接）。打开应用凭证页，取得 **Agent ID（应用 ID）**、**App Key**、**App Secret**。后台字段称呼可能不同：Agent ID 是数字应用标识，App Key 是 SDK 连接鉴权使用的 `appId/app_key`，二者不能互换。
2. 在 aiopsterm 选择 **百度如流**，分别填写上述三个字段。Secret 只填密码框。
3. 授权用户填回调中的 `FromUserId`（私聊）或 `message.header.fromuserid`（群聊），群填 `groupid`。从自己机器人后台的事件调试数据取得这些值，不使用显示名称。私聊回复使用事件中的 `FromUserName`，但授权依据始终是用户 ID。先只授权自己并验证私聊。
4. 按 [百度官方接入指南](https://aca.bce.baidu.com/doc/Dumate/s/Jmr0c3qns)，在机器人设置中打开 **接收消息服务器**，选择 **使用长连接接收回调** 并保存。确保机器人可用范围包含测试成员，按企业后台要求完成启用、发布或审核。若后台没有长连接选项，需要如流管理员确认该机器人是否具备该能力；当前实现没有 HTTP 回调模式。
5. 勾选网关启用并保存，等待已连接。私聊发送 `/help`、`/sessions`；列表中每个终端都带 `/select <一次性令牌>`，复制对应的一整行发给机器人即可绑定。`/new` 和翻页也用列表中的选择命令，不需复制 sessionId。令牌十分钟有效，仅原用户、原聊天可使用一次。
6. 群聊发送需机器人管理员通过机器人底部 Menu 的“开通API权限”启用“以机器人身份发送消息到群聊”。群聊需授权用户与群、将机器人加入群，并通过如流客户端的 @ 选择器明确选中当前机器人后发送正文。只接收 `MESSAGE_RECEIVE` 且消息体中确实包含该机器人 `robotid` 的消息，不接收 `ALL_MESSAGE_FORWARD`。不要手打名称冒充 @。选择命令前同样要 @机器人。

使用公开包 `@core-workspace/infoflow-sdk-nodejs` 0.1.7；其 [README](https://www.npmjs.com/package/@core-workspace/infoflow-sdk-nodejs) 同时列出内网发布名 `@baidu/infoflow-sdk-nodejs`。桌面通过 `infoflow-open-gateway.baidu.com` 建立长连接，通过 `api.im.baidu.com` 发送消息，不监听公网端口。SDK 日志关闭，防止请求凭据及终端正文出现在日志中。

如流平台支持在用户点击交互卡片按钮后，通过回调响应刷新原卡片；此能力已由用户提供的 OpenHub 文档确认。aiopsterm 当前仍使用纯文本列表，尚未实现交互卡片发送、按钮回调和原卡片刷新。无须点击、由应用主动更新卡片的接口仍待确认，不能把按钮回调刷新视为终端输出的自动持续更新。接口证据、现有接入差异及待验证条件见[如流 OpenHub 接口边界](../technical/im-gateway.md#如流-openhub-接口边界)。普通 shell 输出批量回传；TUI 画面连续重绘时等待最后一次终端输出之后 4 秒再发送最终屏幕。动画一直不停时不会持续推送，可随时 `/read` 或 `/screenshot` 主动查看。文本每段最多 1800 UTF-16 单元；所有控制键和断线回复复用通用网关逻辑。

截图走 SDK 图片消息，原始 PNG 必须小于 1 MiB；过大、权限不足或发送失败会回复说明，建议用 `/read`。图片仅取绑定终端，不截桌面。群聊图片使用 SDK `sendToGroup(..., 'IMAGE')`，发送不含 data URL 前缀的 Base64，符合[公开机器人文档](https://qy.baidu.com/doc/index.html#/inner_serverapi/robot)；真实企业的图片权限和投递仍需联调，不能由单元测试证明。

用户提供的 OpenHub 文档规定新机器人群消息发送上限为每机器人 10 QPS；每群每分钟 20 条、超限限流五分钟仅适用于历史自定义机器人。当前适配器仍在每次群发送后保留至少 3.1 秒间隔，这是兼容现有 SDK 接入的保守发送策略，并非新机器人的平台上限。私聊在没有群发送等待时最小间隔半秒。私聊事件若不含 MsgId，使用身份、平台创建时间和正文的哈希去重；同一用户同一秒的两条完全相同正文可能合并为一次，需间隔一秒以上再发相同操作。

如流显示 `IM_GATEWAY_INFOFLOW_RECEIVE_FAILED` 时，检查本机网关状态存储是否可写；SDK 可能已确认这条投递，修复后先查看终端，再发送新消息，不会自动重放输入。

## 验收与故障定位

| 场景 | 预期 |
| --- | --- |
| 私聊 `/help`、`/keymap` | 已授权用户可收到帮助，无需先绑定 |
| 列表、翻页、新建及绑定 | Telegram 点击按钮；如流复制 `/select`；不能操作他人的选择 |
| `pwd`、`ls`、三键组合、ESC | 输入原绑定终端，输出回传；按键不额外回车 |
| 动画输出 | Telegram 编辑同一消息；如流静止后发一次屏幕 |
| `/screenshot`、`/read` | 返回当前绑定终端；解除授权或绑定失效后不再发送截图 |
| 终端断开 | 收到断开通知，再发消息得到绑定失效提示 |
| 非授权用户、未授权群或错误 @ | 不执行终端操作 |
| 切换平台、停用、重启 | 停止旧渠道接收和排队操作，不自动继承其他平台绑定 |
| 平台网络失败 | 可见错误/重连状态；消息发送失败不重放终端输入 |

自动化测试覆盖协议转换、账号隔离、选择令牌、图片边界、输出策略和生命周期；本次未配置真实 Telegram/如流机器人，因此尚未完成真实平台联调。提供上述凭据时应在本机设置页填写，不通过聊天发送密钥。遇到失败，先看设置连接状态和平台后台事件记录；不要把含 Token 的 Telegram 请求 URL 或 SDK 原始请求对象贴入日志。
