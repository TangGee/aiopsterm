# Terminal Workspace

Terminal tabs behave like standalone sessions until a split action groups them.

- The terminal starts on a welcome dashboard background, not a closable tab. There is no toolbar `+` tab button; new terminal sessions come from workspace resource actions or existing command flows. Use the tab or pane context menu to open a local shell, reconnect, disconnect, search, run AI command generation, show the floating command input, broadcast commands, open file management, or adjust font size.
- Terminal tabs show close controls on the active tab and on hover for inactive tabs. Routine `running`/`ready` state text is not shown in the tab label; only exceptional connection states use compact indicators. Each tab also shows compact context metadata: local terminals show the current directory basename, SSH terminals show `user@host[:port]`, and knowledge/editor tabs show their relative path. Hovering a tab shows the full type, state, host, cwd, file path, and backend session id when available.
- The active terminal context bar sits above the terminal grid. It shows the active surface title, local/SSH/editor type, connection state, full host/path context, and pending AI attention count for that terminal. `AI 会话` opens the session manager, `刷新` reloads managed agent state, `聚焦` returns keyboard focus to the active terminal, and `复制上下文` copies a concise text block with title, type, state, host, cwd/file, terminal session id, and pending AI session titles so external tools can pick up the same operational context without scraping the screen. Clicking the AI attention chip jumps to the relevant AI session.
- SSH sessions enable keyboard-interactive authentication. When a remote host or bastion requests a dynamic password, OTP, or other second-factor prompt, the main process forwards the request to a global verification dialog; the response is sent back to the active ssh2 authentication exchange. The dialog is not dismissed by clicking the backdrop, so accidental blank-space clicks do not cancel an in-progress login.
- SSH sessions send backend keepalive traffic by default. Direct, proxy, TCP-forward jump-host, and relay-shell fallback sessions all keep both the relay hop and nested target hop active with the shared SSH keepalive interval, reducing idle disconnects caused by NAT, firewalls, or bastion idle cleanup.
- Password-auth SSH sessions without a saved password open the same global authentication dialog before connecting. The password is session-only by default. If `记住密码并更新该主机` is checked, the backend stores the password only after the SSH connection reaches the ready state. If a saved host password is rejected, the SSH backend prompts once for a replacement password and retries the real connection before reporting failure.
- SSH authentication failures are diagnosed by the main-process SSH boundary. Password-disabled servers, rejected passwords, rejected keys, missing auth methods, and network failures surface distinct backend error codes and actionable messages in the terminal status instead of raw ssh2 text only.
- The command input is not persistent at the bottom of each terminal. Right-click a terminal pane and choose `输入命令` to show it as a floating input near the cursor; it stays open for rejected/unavailable commands and closes after successful shell writes.
- Right-click a terminal tab or terminal pane and choose `向右拆分` or `向下拆分` to split the selected pane region.
- Right-click a split tab or pane and choose `取消拆分` to restore that pane as a standalone tab.
- Drag a terminal or knowledge tab onto another terminal/knowledge tab or pane to attach it as a right-side split of the target.
- Drag a split terminal or knowledge tab onto the tab bar empty area to restore it as a standalone tab.
- Dragging one or more local files onto a terminal or embedded Codex terminal inserts their local filesystem paths into the active shell input. Paths are shell-quoted when needed so spaces, quotes, and other command-line metacharacters remain part of the path.
- Split restore forces xterm host geometry cleanup, multi-frame fit, terminal refresh, scroll-to-bottom, and backend resize notification when a backend session is attached.
- Font-size increase/decrease actions are scoped to the selected terminal pane and force terminal fit/refresh so the input row stays visible.
- Settings -> Terminal updates opened terminal panes and embedded Codex terminal panes for font family, font size, line height, cursor style, cursor blink, and scrollback. Pane-local font zoom still overrides the global font-size value for that pane until the pane is closed. The close-button switch controls tab close buttons, and Pinch Zoom gates Ctrl/Meta wheel font zoom in terminal panes.
- Settings -> Terminal `终端类型` is applied to the frontend xterm `termName` for opened terminal panes and embedded Codex panes, and is passed to new local pty sessions, SSH shell allocation, and relay-shell fallback ptys as the terminal type/`TERM`; invalid or missing values fall back to `xterm-256color`. Terminal history replays suppress xterm-generated query replies so old terminal capability/color queries are not written back into a live shell as visible text.
- Settings -> General background and watermark are applied at the app shell level. Module workspaces, side rails, tab strips, AI/resource panel chrome, terminal menus, command/status bars, AI input controls, and settings/database chrome use translucent surfaces only when an app background is active, so the configured background is visible without making terminal text areas unreadable. The embedded Codex pane enables transparent xterm painting in background mode, then applies the readable dark glass layer on the Codex host instead of inside xterm. Built-in presets are low-distraction layered CSS backgrounds, custom images use visible default opacity/brightness values, and older low-visibility tuning is lifted the next time the user selects a preset or custom background.
- Settings -> Extensions `自动补全` gates terminal command suggestions, and `关键词高亮` gates terminal keyword-highlight rendering without mutating the raw terminal output buffer.

## Keyboard Shortcuts

- When a terminal pane has focus, plain `Ctrl+letter` combinations are delivered to the shell/PTY instead of aiopsterm app actions. This includes readline and TUI control keys such as `Ctrl+a`, `Ctrl+c`, `Ctrl+d`, `Ctrl+e`, `Ctrl+f`, `Ctrl+k`, `Ctrl+l`, and `Ctrl+m`; `Ctrl+a` means holding Control and pressing lowercase `a`, not `Ctrl+Shift+A`.
- Terminal app actions use non-shell combinations: `Ctrl+Shift+C` copy, `Ctrl+Shift+V` paste, `Ctrl+Shift+F` search, `Ctrl+Shift+G` next search match, `Ctrl+Shift+H` previous search match, `Ctrl+Shift+J` clear search highlight, `Ctrl+Shift+K` AI command, `Ctrl+Shift+N` new window, `Ctrl+Shift+Q` close window, `Ctrl+Shift+T` new terminal, `Ctrl+Shift+Y` fork the current SSH channel when available, `Ctrl+Shift+W` close terminal, `Ctrl+Shift+L` clear terminal, and `Ctrl+Shift+M` file manager. `Ctrl+Shift+T` and the terminal context-menu new-terminal action open a new local shell; when launched from a connected local terminal they inherit that terminal's cwd, and when launched from SSH they do not clone the remote connection implicitly. SSH terminal context menus show `Fork SSH` for forkable SSH channels, including jump/relay SSH sessions whose jump host metadata is available. `F11` toggles full screen. On macOS, `Cmd+C` and `Cmd+V` also remain terminal clipboard actions.
- Font zoom uses `Ctrl+=`, `Ctrl+-`, and `Ctrl+0`. Tab navigation uses `Ctrl+PageUp` / `Ctrl+PageDown`, `Alt+1` through `Alt+9` / `Alt+0`, and `Ctrl+Shift+PageUp` / `Ctrl+Shift+PageDown` to move the active tab left or right. Scrollback uses `Shift+PageUp`, `Shift+PageDown`, `Shift+Home`, `Shift+End`, and `Ctrl+Shift+Up` / `Ctrl+Shift+Down` for one-line scroll.
- `Ctrl+Shift+Left` / `Ctrl+Shift+Right` jump to the previous or next known command input segment. aiopsterm can jump precisely for commands submitted through its command/security pipeline; plain shell-typed commands require future shell-integration markers before they can be detected reliably.
- Settings -> Shortcuts can remap configurable app actions such as new terminal and specific-tab switching. If a user-configured app shortcut is a plain `Ctrl+letter`, it works outside terminal focus but is not captured inside terminal panes, so shell/readline control keys stay reliable.
- The right Codex CLI AI panel can follow the main terminal workspace. When the link button in the AI header is enabled, selecting a terminal tab switches the AI panel to an already-bound Codex conversation for that terminal, and selecting a Codex conversation switches the main workspace back to its bound terminal. If the selected terminal has no bound Codex conversation, aiopsterm keeps the current AI tab and shows a bind/new-session hint instead of creating one silently. Turning the link button off returns Codex target selection to manual mode.
- AI 会话管理 tracks coding-agent events when the agent runs inside an aiopsterm-created local shell and reports through the managed agent socket. It also imports recent restorable local history from Codex, Claude Code, and OpenCode state stores so previously resumed/created sessions can appear before a new hook event arrives. Imported rows are idle and telemetry-only until a live hook updates them. aiopsterm injects `AIOPSTERM_AGENT_SOCKET_PATH`, `AIOPSTERM_AGENT_HOOK_PATH`, and `AIOPSTERM_JS_RUNTIME` into local shells, and Settings -> AI Notifications exposes explicit hook installers for Codex, Claude Code, Cursor, Gemini, Copilot, Grok, OpenCode, CodeBuddy, Factory, Qoder, Amp, Pi, OMP, Kiro, and Rovo Dev. It does not silently install global agent hooks. Settings -> Host Agent -> Conversation & Hosts has an off-by-default `AI 会话自动命名` switch that can summarize completed turns with the configured model provider while preserving manual session names. A `stop` turn-complete event enters `待处理` as a review/confirmation item until the owning conversation or another managed-session decision path handles it; `session_end` or terminal close/error marks the bound session ended internally. The manager lives in the left module panel and reuses the main terminal workspace. The top-bar bell is the global pending-AI entry: its badge shows AI sessions that need input, clicking it focuses the owning terminal and opens the session list, and repeated clicks cycle through the remaining pending sessions until they are handled. Pending sessions also highlight the owning terminal tab/pane until handled. Stock Codex permission hooks are visible in the session list but stay local-record only, because Codex keeps its own approval UI.
- The AI 会话 panel is a compact managed-agent inbox. Its top icon buttons switch between `待处理`, `运行中`, and `会话库`; hover tooltips explain each icon, and count badges show pending and running workload without long labels crowding the left panel. `待处理` contains sessions waiting for a user decision, answer, review, or confirmation; completed AI turns stay here until handled by the owning conversation/terminal or another decision surface, then become ordinary library entries. `运行中` shows active agent work grouped by project by default, supports the same collapsible project/agent grouping control as `会话库`, and row selection only highlights the row without changing the active terminal. Row dots use four user-facing groups: running, pending, linked to an open terminal, and other. `会话库` is the all-session history view, but row footers do not expose internal lifecycle states such as `ended` or `idle`, and rows do not show restore or mark-handled buttons. Passive backend refreshes and background status changes do not switch the user's current tab; only explicit navigation such as the top-bar bell or an external focus request opens the matching pending/running/library view. Selecting or double-clicking a row inside `会话库` keeps the panel on `会话库`; double-click only locates/restores the terminal. Rows show the stable title plus latest real detail/summary in a compact stack; duplicated title/summary text is still shown so a one-line truncated title has a readable multi-line fallback, while synthetic close summaries such as `Terminal closed` stay out of list rows. Narrow rows can show the summary/detail up to three lines. The lower meta line uses `agent · branch* · project · time`; branch appears only when aiopsterm can read git metadata, and `*` marks a dirty working tree. The project label is width-aware: wider rows can show a longer shortened path, while narrow rows fall back to a compact project name with duplicate markers such as `①` and `②`. Full paths remain in tooltips instead of cluttering every row. The session library groups rows by canonical project path by default, so symlink aliases collapse into one project while genuinely different projects with the same basename keep separate markers; it also supports collapsing each group and can switch to agent grouping from the compact grouping control. Double-clicking a row locates its owning terminal when it is still open; if no terminal is open and a resume command is available, aiopsterm opens a local terminal at the saved cwd and writes the resume command through the normal terminal command security path while keeping the AI session panel open. The panel refresh button rescans managed AI conversations, git metadata, and status. The global top-bar bell remains the primary way to cycle through sessions that need input.
- When many terminal tabs are open, tab titles shrink and ellipsize so later tabs remain reachable.
