# AI 助手与会话管理

aiopsterm 的 AI 能力分三层：右侧 **AI 侧栏**（Codex CLI / Classic 对话）、**Agents 模式**（产品会话目录）、**AI 会话** 模块（编码代理收件箱）。本文说明各自定位与推荐工作流。

## AI 侧栏

![AI 侧栏](../images/ai-panel.png)

| 编号 | 元素 | 说明 |
| --- | --- | --- |
| ① | 模式切换 | 在 Codex CLI 与 Classic 对话之间切换 |
| ② | 对话消息区 | 助手回复以净化后的 Markdown 渲染，代码块带复制按钮 |
| ③ | `@ 添加上下文` | 显式选择主机、知识文档、历史对话作为上下文 |
| ④ | 输入框 | 支持 `/` 引用快捷命令、`@` 引用主机与文档 |
| ⑤ | 模型选择 | 切换当前对话使用的模型 |
| ⑥ | 发送 | 任务运行中变为 Stop，可随时中断 |

Classic 对话有三种模式，权限逐级放开：

| 模式 | 能力 | 适用场景 |
| --- | --- | --- |
| Chat | 纯问答，不声称能操作终端 | 咨询、解释概念 |
| Command | 生成**一条**命令提案，只待人工审查，绝不自动执行 | 想要"帮我写条命令" |
| Agent | 受控分析工具 + `run_host_command`，按审批执行 | 多步排查、巡检 |

上下文行为要点：

- 上下文默认为空，主机必须通过 `@` 显式加入（每轮最多解析 5 个 `@host`），模型只能从这份白名单里选目标，无法凭空指定 IP 或凭据。
- 每张命令卡都标注目标主机；`执行` 需要卡片绑定的后端终端会话存在，不会悄悄退回"当前活跃终端"。
- Command 提案在执行前可编辑保存；Agent 模式待审批的命令则不可修改——主进程只执行它审批过的那条命令。
- 图片输入仅支持 JPEG/PNG/GIF/WebP，单张 ≤5 MiB，每条消息 ≤5 张，超限立即提示而不是静默丢弃。

> 安全边界：只读命令自动执行开关（`查询类自动执行` / Settings -> 主机Agent 的 `自动执行只读命令`）只对模型声明为非破坏性的诊断命令生效；主进程安全策略永远可以否决模型的声明。被策略拦截的命令保持拦截。

## Agents 模式：管理所有产品会话

![Agents 模式](../images/agents-mode.png)

**① 模块导航栏最上方的 Agents 图标**进入 Agents 模式。**② 搜索框** 按标题、载体、绑定、项目过滤；**③ 会话行** 单击恢复到 **④ AI 侧栏**。

![新建会话菜单](../images/agents-new-menu.png)

点 **① `+`** 打开新建菜单 **②**，可选三种载体：

- **Classic**：主机管理 AI 对话（Chat/Command/Agent）。
- **Codex**：绑定终端与项目 cwd 的 Codex CLI 会话；恢复时会复用或重连原终端。
- **DB AI**：离开 Agents 模式、打开数据库工作区并恢复保存的连接/库/Schema。

![恢复会话](../images/agents-restore.png)

点击 **① 会话行** 后，右侧完整恢复历史transcript（**②**），可在 **③ 输入框** 直接续聊。恢复总是定位到最新消息；向上滚动按页加载更旧的消息，且不会把旧 UI 消息加进模型上下文。

> 最佳实践：为每类常规工作维持一个命名清晰的会话（如"生产巡检"、"K8s 发布失败"），Close 只关闭 UI 并停止运行时、保留会话可再恢复；Delete 才是永久删除。应用重启后不自动恢复任何会话——一切从 Agents 目录找回。

## AI 会话模块：编码代理收件箱

![AI 会话模块](../images/ai-sessions-inbox.png)

**① 模块导航栏的 AI 会话** 是托管编码代理（Codex、Claude Code、OpenCode 等）的收件箱，不同于 Agents 的产品会话目录。启用 Agent Hook 后（Settings -> AI 通知 提供各代理的一键安装器），在 aiopsterm 本地终端里运行的代理会话会实时出现在这里，本机历史也会自动导入。

三个视图：

- **待处理**：等待你决策/回答/确认的会话。顶栏铃铛是全局待处理入口，徽标数字表示需要输入的会话数，连点可在多个待处理会话间轮转。
- **运行中**：默认按项目分组的活跃工作。
- **会话库**：全部历史，支持按项目/按代理类型/纯时间三种组织方式。

常用操作：双击行定位或恢复所属终端（可恢复的空闲会话会在保存的 cwd 打开本地终端并写入 resume 命令）；右键 `打开会话内容` 在主工作区浏览、甚至编辑本地 transcript（保存前自动做修订检查并备份到 `agent-sessions/content-backups/`）。

> 提示：编辑过 transcript 后需重启该 AI 对话才会生效——运行中的代理在内存里保留着旧上下文。

## 观察和编辑 AI 修改的项目文件

![AI 项目文件](../images/ai-project-files.png)

图中 **①** 是项目和能力标识，**②** 是最近变更，**③** 是按需加载的项目树。

当托管 AI 会话绑定到本地项目后，从右侧 AI 会话工具栏打开 **项目文件**。这个抽屉把 AI 的会话状态和磁盘上的真实文件放在同一个工作区：

- **最近变更**按创建、修改、删除、重命名显示由 Agent Hook 或显式文件变更事件报告的文件。
- **项目树**按需加载目录，可新建、重命名、移动和删除项目内文件。
- 点击文件进入 Monaco 编辑器。编辑内容会在停顿约 1 秒或输入框失焦时自动保存。
- 编辑器持续观察磁盘版本。若 AI 或其他程序在你编辑期间改了同一文件，会要求选择**重新加载**或**覆盖**，不会静默吞掉任一方的修改。

文件能力会标为 `Native`、`Adapter` 或 `Limited`。它只允许访问会话绑定项目的规范化路径；任何越界路径都会被拒绝。最近变更来自代理原生事件、已识别的文件工具或显式上报，普通 shell 命令造成的任意磁盘变化不会被猜测为 AI 变更。

典型工作流：

1. 在 **运行中** 视图打开目标会话，确认项目路径正确。
2. 展开 **最近变更**，先看重命名和删除，再抽查修改文件。
3. 需要修正时直接编辑；发生冲突先重新加载并合并，只有明确要以当前内容为准时才覆盖。
4. 回到终端运行测试，再通过通知或会话状态确认任务完成。

## 通知和自定义提示音

![AI 通知设置](../images/settings-ai-notifications.png)

从左侧 **① AI 通知** 进入设置，**②** 选择是否播放通知声音，**③** 导入或试听自定义声音，**④** 管理不同编码 Agent 的 Hook。

打开 **设置 -> AI 通知** 安装对应 Agent Hook，并配置桌面通知、控制栏铃铛和声音。声音可选内置提示音，也可导入 MP3、WAV、OGG、M4A、AAC、FLAC 或 WebM 文件；导入后文件会复制到用户数据目录的 `notification-sounds/`，因此移动原文件不会破坏配置。保存前可直接试听。

建议按事件强度设置：

- 普通进度只进入 AI 会话列表，避免频繁打断。
- 审批、提问和确认同时显示桌面通知并播放较短提示音。
- 完成和错误使用不同声音，离开屏幕时也能判断是否需要立即处理。

顶栏铃铛优先轮转需要输入的托管 AI 会话。开发工具通过 `aio notify` 发送的通用通知也可进入控制通知队列，但它与托管 AI 会话通知是两套数据：通用通知不会自动创建或更新 AI 会话。

## 规则与模型

- Settings -> 主机Agent -> 规则 里启用的 User Rules 会注入每个 Classic 对话，用来约束回复风格与工作流；但它不能越过主机白名单、终端安全策略与审批要求。
- Settings -> 模型 管理内置与自定义模型；OpenAI 兼容端点的 Base URL 若已含 `/v1` 会被保留，结尾加 `#` 可阻止自动追加 `/v1`。
