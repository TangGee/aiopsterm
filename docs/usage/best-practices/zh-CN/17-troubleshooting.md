# 故障排查

本文只介绍安装版中用户可以自行完成的检查。遇到问题时，先确认入口、配置和当前作用域，再收集日志。

## 从哪里打开

点击左下角 **设置 -> 关于**，可查看版本、复制诊断信息并打开日志目录。AI 通知和外部会话 Hook 在 **设置 -> AI 通知**；Host Agent 的模型和 MCP 在 **设置 -> 模型**、**设置 -> 主机 Agent**；导出给外部 Agent 的 MCP 在 **设置 -> 导出 MCP**。

![关于与日志入口](../images/settings-about.png)

## 安装后无法打开

- macOS 提示无法验证开发者或应用已损坏：确认安装的是正式发布的已签名、公证 DMG，并把应用拖入“应用程序”后再打开，不要长期从 DMG 中直接运行。
- Windows 被 SmartScreen 拦截：核对发布来源和文件校验值，再从系统提示中查看签名信息。
- Linux 启动失败：确认使用与当前架构匹配的安装包，并从系统应用菜单启动一次。

若应用曾被手工修改、解包或替换内部文件，签名会失效，应重新安装原始发布包。

## 终端没有输入、配色或布局异常

1. 在终端工作区点击目标终端标签，确认焦点位于终端而不是搜索框或侧栏。
2. 右键终端，检查只读、广播输入、布局和终端设置。
3. 到 **设置 -> 终端**确认字体、字号、行高、字间距、Shell 与配色；恢复默认值后重新创建一个本地终端作对照。
4. 只有某个远程终端异常时，重新连接该主机；所有终端都异常时，重启应用并从 **设置 -> 关于**打开日志目录。

## SSH、代理与跳板机连接失败

先到 **资产 -> 主机**打开资产编辑页并点击连接测试：

- 直连主机：检查地址、端口、用户名以及密码/私钥。
- 标准 SSH 跳板：检查跳板主机本身可连接，并确认目标主机允许从跳板访问。
- relay-shell：认证提示会出现在终端中，需要在终端完成动态口令或第二跳认证。
- JumpServer：检查服务地址、账号或令牌，以及资产同步权限。

连接超时通常表示网络、代理或防火墙问题；认证失败通常表示用户名、密钥、密码或动态口令不匹配。relay/跳板链路无法提供 SFTP 时，文件模块会明确显示不支持，可在终端使用 `scp` 或 `rsync`。

## Host Agent 无法发送或工具不可用

1. 到 **设置 -> 模型**完成 Provider 配置，并执行 **Check**、**Save**。
2. 内嵌 Codex 使用 **OpenAI Compatible**，API Format 必须选择 **Responses**。
3. 到 **设置 -> 主机 Agent**确认模式、模型和工具开关。
4. 回到主机 Agent，重新绑定目标终端后再发送。

Classic AI 可使用更多兼容格式；内嵌 Codex 与 Classic AI 的会话和配置互不替代。完整步骤见[主机 Agent](03-host-agent.md)。

## 外部 AI 会话、文件修改或通知没有出现

这部分只针对外部 Codex、Claude Code、OpenCode 等会话：

1. 到 **设置 -> AI 通知**安装对应 Hook；修改配置后重新安装一次。
2. Codex 中要启用并信任插件/Hook，否则 aiopsterm 收不到实时事件。
3. 从 aiopsterm 管理的本地终端启动 Agent。历史导入可以补会话，但不能代替实时事件。
4. 检查系统通知权限、aiopsterm 的通知与声音开关，以及勿扰模式。
5. 打开 AI 会话行菜单，确认能打开完整对话内容和项目文件。

Host Agent 或 Agents 产品会话不依赖外部会话 Hook，不要用 AI 会话列表判断它们是否运行。详见 [AI 会话管理](05-ai-sessions.md)。

## MCP 方向配置错误

- 想让外部 Codex/Claude 调用 aiopsterm：使用 **设置 -> 导出 MCP**，安装终端、知识库或数据库 MCP。
- 想让 Classic AI 调用第三方 MCP Server：使用 **设置 -> 主机 Agent -> MCP** 添加并启用服务器。

这两个方向相反。详见[导出 MCP](08-export-mcp.md)和[第三方 MCP Server](09-third-party-mcp.md)。

## DB AI 无法使用

确认模型已 Check/Save，数据库已连接，并在 SQL 标签中选择了有效 connection、database、schema。上下文变化后会创建新的 DB AI 会话；恢复旧会话时必须恢复它原来绑定的数据库范围。生成 SQL 只有在作用域未变化且语句只读时才能直接运行。

## Kubernetes AI 或命令失败

先确认 kubeconfig、当前 context、namespace 和 RBAC。顶部 Agent 命令栏是受控 `kubectl` 操作入口，不是大模型；需要 AI 分析时，先配置模型，再从资源详情、日志或终端输出中点击 **发送输出到 AI**。

## 提交问题前

请附上：

- 复现步骤和发生时间；
- **设置 -> 关于**中的版本和诊断信息；
- 日志目录中对应时间段的 `aiopsterm-runtime.log`；
- 不含密码、私钥、令牌的截图。
