## 定位与受众

对外总定位沿用项目事实：“为人和 AI 打造的运维终端”。视频解释为：“把主机连接、AI 排查和任务会话放进一个工作区”。这是内容定位建议，不是经过投放验证的市场结论。

| 优先级 | 受众及具体困扰 | 第一条视频要证明什么 | 看完后的单一行动 |
| --- | --- | --- | --- |
| 主线一 | 经常使用 SSH 的运维、SRE、DevOps 和开发者；把日志复制到 AI，再复制命令回来 | AI 能针对明确绑定的终端读取证据、执行可见操作，并让用户核对结果 | 下载匹配版本，在测试主机完成一次只读诊断 |
| 主线二 | 同时运行多个编码 Agent 的开发者；不知道哪个会话在等自己、改了哪些文件 | 运行状态、等待处理、终端定位和项目文件可集中查看 | 在一个受支持 Agent 上安装 Hook 并收到一次真实通知 |
| 新版本扩展 | 已有用户，希望离开桌面后查看或操作终端 | 飞书卡片选终端、发送输入、查看截图和控制键形成真实闭环 | 完成机器人配置，绑定一个测试终端 |

当前补录范围包括 AI 会话通知、阿里主机 Classic、内嵌 Codex、Kubernetes、SQL 和飞书启动 Codex。各场景交付独立原片，供用户剪辑；首条介绍片可从中选择关键结果，不必逐项讲解全部模块。

| 场景 | 必须拍到 | 边界与验收 |
| --- | --- | --- |
| AI 会话通知管理 | 外部 Agent 真实任务触发通知，从通知定位会话，查看并编辑对话记录 | 这是 AI 通知/会话模块，不是右侧 AI；编辑专用演示会话，停止 Agent 后保存，确认保存和重新读取结果；当前编辑不自动备份 |

| 飞书启动 Codex 编程 | 在飞书发送 `/sessions`、点击卡片绑定演示终端（不手输 UUID）、直接输入 `codex` 进入交互界面，发送自然语言任务并继续追问，查看实际文件及测试结果 | 不使用 `codex exec` 代替交互编程；编程限定独立测试目录；桌面应用保持运行；聊天及桌面变化必须来自同一次真实操作 |

建议增加“AI 项目文件”镜头：从会话找到 Agent 修改的文件，在编辑器核对内容，接在通知与对话片段后。该镜头是补充建议，不能把未拍内容列为已交付。暂不为凑功能数量扩展主题、MCP 或全部设置页。

## 主宣传片逐段脚本

场景选一个可重复的测试故障，例如本地容器中的反向代理上游端口配置错误。先复现，再录制；如果实际排查未找到原因或修复未验证成功，就不能套用“已修复”的结尾。

| 时间 | 画面与操作 | 字幕或口播草案 |
| --- | --- | --- |
| 0–4 秒 | 同屏给出服务 502 和已经验证的 200 结果片段，标明是前后对照 | “服务返回 502，AI 能直接帮你查到哪里出了问题吗？” |
| 4–12 秒 | aiopsterm 中打开命名清晰的测试 SSH 主机，显示终端与 AI 面板 | “连接你的测试主机，把 AI 绑定到这个终端。” |
| 12–22 秒 | 输入任务：检查反向代理和上游，只诊断，不修改配置 | “先读取真实日志和配置，不靠粘贴截图猜原因。” |
| 22–42 秒 | 保留工具目标、命令、关键输出；对等待进行明确标注的剪辑 | “每一步都能看到目标和依据。” |
| 42–55 秒 | 放大上游地址与服务监听端口，显示模型提出的具体修改 | “问题定位到这一处端口配置。” |
| 55–68 秒 | 若修改确实触发审批，保留审批及执行画面；仅修改测试环境 | “确认操作后，再执行修复。” |
| 68–80 秒 | 重跑请求得到 200，核对日志；不能只展示模型说成功 | “重新请求，确认服务恢复。” |
| 80–90 秒 | 产品名、版本状态、一个下载或入门入口 | “aiopsterm，为人和 AI 打造的运维终端。先在测试主机完成一次诊断。” |

前后对照必须来自同一次真实演示。剪辑压缩等待需标注，不能把视频长度说成真实故障处理耗时。AI 面板在录制时预留足够宽度；关键输出做局部放大，不让观众读整屏小字。主机 Agent 的能力和边界以[使用指南](../usage/best-practices/zh-CN/03-host-agent.md)为准。

## 两条重点短片的镜头约束

会话管理短片：开头直接展示“有一个 Agent 正在等你”，再用会话列表或铃铛定位，最后查看它的问题或项目文件。实时状态来自真实 Hook；不使用 `aio notify` 冒充 Agent 任务事件。原生 Codex 的审批在其终端中处理，不把 aiopsterm 描述成代替 Codex 审批的控制台。参考[会话管理指南](../usage/best-practices/zh-CN/05-ai-sessions.md)。

飞书短片：桌面与聊天并排或交替特写。先选终端，再输入命令，再收到输出或截图，最后发送控制键并验证目标程序反应。普通消息交给已绑定终端内程序，不描述成机器人自行理解自然语言；all 是终端授权范围，不是允许所有用户。桌面应用必须运行，不能宣传成关机仍可用的云服务。两侧使用专门的演示聊天与终端；当前录好的设置页片段只用于解释配置。参考[飞书指南](../usage/im-gateway.md)。

## 画面与交付规格

先制作中文横屏母版：1920 x 1080 为后续录制目标，30 fps，H.264 MP4，关键文字在手机上缩小预览后仍可辨认。当前 1600 x 900 的工作区素材可复用，不把放大导出称作原生 1080p 细节。

主片建议配中文解说和独立字幕；功能短片可只用字幕。没有合适配音时先交付字幕版，不影响理解。需要配音时另行录制或生成，当前成片无音轨。保留干净画面、SRT、字幕版和封面，方便后续语言版本。

横屏先用于产品页、README 链接和完整演示。竖屏版本只选一个动作，通过重新布局或裁切特写制作，不能把整个桌面缩成一块小字。B 站可作为中文完整演示的首轮试验渠道，其他社区用于相关场景的短片和说明；这是待验证的渠道选择，不依赖未核实的平台流量或算法承诺。当前没有发布账号数据，不能声称这些渠道已经有效。

封面采用“一个问题 + 一个结果”，例如“SSH 连上以后，让 AI 接着排查”“哪个 Agent 正在等你？”；避免“最强”“全自动接管”“彻底替代运维”或没有证据的效率倍数。

## 效果判断

先记录基线，不虚构既有数据，也不承诺固定播放量或转化率。

- 看懂：目标观众能否在看完后说出产品解决的具体任务；首轮可邀请少量实际使用 SSH 或编码 Agent 的用户反馈，不把小样本视为市场结论。
- 观看：平台若提供开头留存、平均观看时长和完播率，按同平台、相近长度视频比较。不同平台定义可能不同，不直接横比。
- 尝试：内容对应下载入口点击、下载、完成一次目标操作。渠道区分链接和首次成功操作统计是待落地项，不宣称已接入。
- 使用：一周内是否再次使用该场景，常见失败卡在哪一步。优先使用现有匿名统计和用户自愿反馈，不采集终端内容或凭据。

如果观看较高但没人尝试，先检查受众、下载路径和教程；如果下载后失败，先修首次使用流程；如果某条短片带来明确的使用反馈，再加同类内容。播放量、Star 和注册数不能单独证明产品已被持续使用。

## 素材验收

每条视频需核对：画面中的版本与下载版本一致；功能完成链路真实可见；字幕没有扩大权限或省略运行前提；没有凭据或不应公开的主机、项目和聊天内容；完整解码无错误；字幕不遮关键按钮、输出与审批；演示服务和临时窗口在结束后关闭。
