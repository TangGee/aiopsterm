## 实际拍到的内容

在 aiopsterm 内通过真实 SSH 连接到仅向 localhost 暴露 SSH 端口的演示容器。代理配置错误导致 `/health` 返回 502；选择 Demo API Gateway 作为 AI 上下文，要求先只读诊断。AI 实际读取配置、代码和日志，核对监听端口，发现代理使用 18082 而应用监听 18081。

录制过程中测试镜像缺少 `ss`、`netstat` 和 `lsof`，AI 改为读取 `/proc/net/tcp*` 检查监听。这个过程是真实诊断的一部分，不需要把缺少工具包装成产品故障，也不能把它剪成第一次命令直接成功。

随后明确授权修复，AI 提交需确认的写命令，备份原文件并仅修改测试配置中的端口。AI 执行差异检查和 curl，取得 `HTTP_STATUS=200` 及 `{"service":"demo-api","status":"healthy"}`。结尾由操作员再次输入 curl，展示完整 HTTP 200 响应。没有手工替 AI 修改配置，没有生成或替换模型回复。

本次使用恢复可用的 `ark-code-latest` 和 Classic Chat / Cline Agent。素材不是原生 Codex CLI 演示，也不证明此前 Code-CLI 账号或多 Agent 会话录制阻塞已经解决。
